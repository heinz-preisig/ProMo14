ARCHITECTURE (Command Automaton)
----------------------------------
Single useReducer in App.tsx. All state changes go through one door:

  Event → Command → applyCommand(state, cmd) → new State

Commands are a discriminated union in src/state/ModelState.ts:
  insertNode | deleteNode | insertArc | deleteArc | moveNode | setView |
  selectNode | selectArc | groupNodes | reconnectOpenArc | moveKnot | addKnot | removeKnot | reset

New commands added by extending Command union + applyCommand switch case.

IMPLEMENTED
-----------
- Command Automaton: single useReducer in App.tsx, all state via applyCommand
- Commands: insertNode | deleteNode | insertArc | deleteArc | moveNode | setView |
  selectNode | selectArc | groupNodes | reconnectOpenArc | moveKnot | addKnot | removeKnot | reset
- Three-layer architecture: flat model graph (semantic) → hierarchy tree (organizational) → GraphViews (visual)
- Three-panel layout: ancestors (left), children (center), siblings (right), connector (top)
- Coordinate system centered: (0,0) is canvas center via wrapping Konva Group
- Canvas click creates leaf node at cursor position (centered coords)
- Nodes render with catalogue-resolved graphical definitions (fill, stroke, radius from SemanticCatalogue)
- Arcs render with catalogue-resolved graphical definitions (stroke, dash, strokeWidth from SemanticCatalogue)
- Arc creation between leaves (select source, right-click target) via connection-rule resolver
- Valid/invalid hover feedback: green ring for valid targets, red ring for invalid
- Arc type selector in properties panel shows valid types for current hover
- Status bar shows connection feedback
- Node selection, arc selection, knot selection, delete (key or button)
- Double-click composite → zoom into (setView)
- Double-click leaf → zoom into leaf view; click empty canvas to add child and convert leaf into composite
- Group selected leaf into composite
- Interactive arc knots: drag to move, double-click to add, right-click to remove
- Knot positions stored in knotStore (Map<arcIri, Knot[]>)
- Unified SceneObject[] for nodes, arcs, open arcs, knots, and reconnect handles
- Generic SceneRenderer and uniform interaction callbacks
- Pan (middle-drag) and zoom (scroll wheel)
- Reset all button
- IRI-based semantic contracts: SemanticCatalogue, ConnectionRuleResolver
- In-memory placeholder catalogue + placeholder rule resolver (allows all)
- Shared connectionService: resolveConnection + pickArcType (used by arc creation and reconnection)
- 35 unit tests passing (TreeOps: 14, ModelState: 1, buildScene: 11, connectionService: 9)
- TypeScript compiles clean
- Flat RDF topology, separate hierarchy, base-entity references, domains, connection rules,
  recursive composition, and graphical-assignment workflow documented in ADR-004

PENDING / KNOWN ISSUES
----------------------
- No save/load persistence yet (next step: define RDF topology + hierarchy/layout persistence boundaries)
- reconnectOpenArc implemented for dangling ends created by leaf-to-composite conversion
- No direct arc endpoint reconnection for regular arcs (must delete and recreate)
- No insertModelIntoModel (compose one model into another)
- Arc rendering may clip at canvas edges
- No drag-to-create-arc (only right-click to connect)
- Connection-rule resolver wired into arc creation and reconnection (placeholder allows all; ready for real ontology rules)
- No real ontology backend yet (placeholder catalogue + resolver in place)
- Knot insertion: addKnot appends to end of knot array regardless of click position along arc; knots render in array order, not geometric order. Future: sort by polyline projection.

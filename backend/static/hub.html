What am I looking at?

Each row is an artefact line — a named, versioned graph in the store. The type decides which app opens it:

ontologyOntology Editor — vocabulary: entity types, domains, tokens, indices, capabilities
libraryEquation Editor — variables and equations (the var/expr artefact)
assignmentBehaviour Linker — equation sequences per entity type
model / glassModeller — topology, placements, species gestures
speciesSpecies — components, allocations, reactions ({A,B} → {C})

Status — draft is the editable working copy; frozen versions are immutable snapshots (open them read-only, export an ontology version as .ttl).

Pins — which artefacts this one builds on. Chips are labelled by pin kind: ont:name = usesOntology (green), spec:name = usesSpecies (purple). Pin a frozen version for reproducibility.

Actions — Open edits the draft; view opens a frozen version read-only. Instantiate a model (instantiation view), Species… pins a scheme to a model, Fork duplicates the artefact to a new IRI — branch it without touching the original. Or click a stage in the suite map — it opens the app directly when the artefact is unambiguous.

Store — all apps share one server-side store; ● unsaved changes means nothing is on disk yet — Save writes one .trig per artefact line.

Mode — the top-right toggle switches where Open sends you. user: the backend-served builds (:8000/modeller/ …) — the normal path. dev: the vite dev servers (:3001–:3006) — hot reload and devtools for frontend work. The label shows the current mode and where a click takes you.

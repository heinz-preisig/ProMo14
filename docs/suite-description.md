To be on the save side, let me provide a picture on how we build models. In the ontology, we define what basic bricks = fundamental entities, are used in the model building process. In the equation editor we define the mathematical description of their behaviour. In the behaviour linker, a list of selected equations describe the input/output behaviour. These are the base entities from which the model is being assembled in the modeller on which we now work.  The model being generated can afterwards again be used in the same way as the base entities were used to build the model in the first place. Thus the format of the model entities and assembled models is identical. RDF is my suggestion for the model graph. Thus each model, including the base entities are RDF knowledge graphs which in the modeller are combined to larger models. These models can be large, in fact very large like millions of nodes if one thinks of distributed systems mapped into graphs of connected lumped systems. In a long run, not now, it will be desirable to have graphical objects representing the composite nodes. The next step will be instantiation of model-defining constants and parameters. These are to be added to the RDF representation enriching the model. Next stage is code generation to enable numerically solving specified problems.
